## 2. 🔴 最重要: Sign in with Apple の2度の障害と真因

### 起きたこと

Apple ログインを実装するたび、本番の `/sign-in` が次のエラーでアプリ全体クラッシュ。

```
useUser can only be used within the <ClerkProvider /> component.
```

- **1度目**（`61cd214d0`）: `clerk-sign-in.tsx` に `lib/auth-providers` の import を足した
- **2度目**（`64dfdb5af`）: import を足さない形にした。**それでも再発した**

### 真因（2度目の失敗で確定）

`components/auth/auto-x-return-notice.tsx` が `useUser()` を**ガードなしで直接呼んでいる**こと。

`ClerkRootProvider` は `app/_layout.tsx` で**動的 import** される設計（バンドル分割維持のため。
同ファイル 32-45 行に経緯のコメントあり）。解決前に `AutoXReturnNotice` が描画されると落ちる。

つまり**元から壊れやすい構造**で、Apple 対応の変更は Metro のチャンク分割のタイミングを
ずらす引き金にすぎなかった。「import を足さなければ安全」という仮説は誤りだった。

### 修正（ブランチ `fix/auto-x-return-notice-guard` = `46b6f7e5d`）

`useUser` への依存を外し、`window.Clerk` の任意参照に置き換えた。
この通知は「Xから戻ったのに未ログイン」を案内するだけで厳密な認証状態を必要としない。
判定できない間は「未ログイン」扱い（未ログイン向けの通知なので実害なし）。

ローカルの Web ビルドで ClerkProvider エラーが消えたことを確認済み。

### ⚠️ 検証の限界（次のセッションが最も注意すべき点）

**ローカル検証は2度とも「問題なし」を示しながら、本番で壊れた。**
`pnpm check` 0エラー・テスト409件green・ローカルの実ブラウザ確認、すべて通過していた。

- localhost では Clerk 本番キーのドメイン制限エラーが出るため、Clerk の実際のマウント挙動を再現できない
- Metro のチャンク分割は本番ビルドでしか確定しない

したがって **「ローカルで確認したから安全」とは言えない**。デプロイ後に必ず本番の
`/sign-in` を実ブラウザで開き、コンソールエラーを見ること。

### 壊した場合の復旧手順（2度実施して有効性を確認済み）

1. `git revert` して push
2. **それだけでは不十分**。`theme/tokens/index.ts` の `CDN_CACHE_EPOCH` を +1 する
   （Metro は子チャンクの参照先URLを親チャンクのハッシュに含めないため、壊れたコードを
   一度踏んだブラウザには CDN の immutable キャッシュ経由で古いチャンクが残り続ける）
3. デプロイ後、**新しいタブ**で本番を開いて復旧を確認

## 5. 地雷・注意点

### DBマイグレーションの手順（4つの罠）

1. **`pnpm db:push` は使えない**。`db-journal-doctor` が件数不一致で止める
2. **`scripts/migrate.ts` は `.env.local` を自前で読まない**。こう実行する:
   ```bash
   node -e "require('dotenv').config({path:'.env.local'});require('child_process').execSync('npx tsx scripts/migrate.ts',{stdio:'inherit',env:process.env})"
   ```
3. **migrate 後も `drizzle.__drizzle_migrations` に記録が入らない**。手動で
   INSERT が必要（hash は SQL ファイルの sha256、created_at は `_journal.json` の `when`）。
   最後に `node scripts/db-journal-doctor.cjs` が OK を返すことを必ず確認
4. **drizzle-kit が見るのは `drizzle/schema/index.drizzle-kit.ts`**。`index.ts` だけに
   export を足しても「No schema changes」と言われる。**両方に足す**

### 設計上の判断（変えるときは設計書を先に読む）

- 場所メモは**地図ピンに出さない**。FootprintSheet（地図の外側）にのみ表示
- `TrailPoint.address` は逆ジオ由来の**事実専用**。ユーザー入力は `placeName` に入れる
- モデレーションを **`encounter.checkIn` に相乗りさせない**（最悪10秒かかる）
- プレミアム判定は**フェイルクローズ**（行なし・DB落ち＝すべて無料）

### 🔴 Vercel Serverless の未解決 Promise

`modules/encounter/api/encounter.ts` に警告コメントあり）。
