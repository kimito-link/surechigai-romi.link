## iOS: 5回失敗していた真因（重要）

`run#481`〜`#485` が全て失敗していた。エラーは
「The bundle version must be higher than the previously uploaded version: '480'」。

**真因**: Expo prebuild が生成する `Info.plist` は `CFBundleVersion` に**リテラル `1`** を書き、
`$(CURRENT_PROJECT_VERSION)` を参照しない。そのため
- `pbxproj` に 485 を書いても
- `xcodebuild` に `CURRENT_PROJECT_VERSION=485` を渡しても
- → **IPA の `CFBundleVersion` は `1` のまま**

ログの `httpBody` が `{"cfBundleVersion":"1"}` を送っていたのが決定的証拠。
同じステップで `CFBundleShortVersionString` は PlistBuddy で Info.plist に書いていたのに、
`CFBundleVersion` だけ書いていなかった**非対称**が原因。

**なぜ5回も繰り返したか（こちらが本質）**: アップロード前の検証ステップが
`CFBundleShortVersionString` **だけ**を見ていた。だから IPA が壊れていてもゲートは緑になり、
Apple に投げて初めて失敗する。ステップ名も
`Verify IPA CFBundleShortVersionString` で、何を見ていないかが名前からも分からなかった。

→ `c9d7b6260` で修正。両方を検証し、ステップ名も `Verify IPA version and build number` に変更。
**今日 Gate 1 で見つけたのと同じ「緑なのに何も検査していない」病理。**

## Xアカウント切り替え（実機確認が必要）

**真因**: X 側のブラウザセッションが生きていること。**OAuth では解決できない**。

| 事実 | 出典 |
|---|---|
| X は OAuth 2.0 で `force_login` 非対応（1.0a 専用） | X スタッフ明言 2025-02 |
| `prompt=login` の要望スレは実装されず 2024-11 close | X 開発者フォーラム |
| Clerk の同症状 issue は "Closed as not planned" | clerk/javascript#6691 |
| `oidcPrompt` は型にあるが `enterprise_sso` でしか送られず `oauth_x` では破棄 | clerk-js 実装を実読 |

→ **x.com/logout をユーザーに踏んでもらう以外に手段がない。**

**設計の背骨**:
1. アプリのセッションは「切り替えに進む」を押すその瞬間まで触らない。
   破棄の直後に必ず `/sign-in` への遷移が続くので、
   **ログアウトされた状態のアプリを見る瞬間が構造上存在しない**
2. X のログアウト完了は検知できないが、**切り替えの成否は事後に検知できる**。
   旧 `twitterId` をスナップショットして帰還後に比較し、同じなら
   「切り替わっていないようです」でやり直せる

**⚠️ 絶対にやってはいけないこと**:
- `x.com/logout?redirect_after_logout=` — 動くが**未修正のオープンリダイレクト脆弱性**。禁止
- 「X の Logout Callback URL 機能」— **存在しない**。会議のモデルが Auth0 と OIDC を
  混同した幻覚（一次情報で確認済み）
- 先に `signOut()` してから案内 — その瞬間に「足あとが消えた」誤解が始まる

**実機確認をお願いしたいこと**（Xアカウント2つ必要）:
マイページ → 設定 →「別のXアカウントに切り替える」→ 別タブで x.com/logout →
戻って「2. ログアウトしてきた」→ **X のログイン画面が出るか**（前のアカウントで素通りしないか）

## ログインボタンが Apple/Google の規約に抵触していた（修正済み）

linktree がミクチャの UX を調べる過程で発見したものを輸入（`144ae34a7`）。
`lib/clerk-appearance.ts` は冒頭に「kimito.link からの忠実コピー」と書かれたまま旧実装を保持していた。

- Apple HIG: "Make a Sign in with Apple button **no smaller than** other sign-in buttons"
- Google: "at least as prominently ... approximately the same size and similar visual weight"

旧実装は「X を大きく・Apple/Google を小さく薄く（opacity 0.7〜0.85）」で**両方に抵触**。
しかも規約リスクを負いながら事故は防げていなかった（Google の「最後に使用したもの」バッジは
Google 側が描画するのでこちらのサイズでは打ち消せない）。

→ サイズ・視覚的重みを3つとも同一にし、主役化は**規約が縛らない自由度**（色・順序）に移した。
アイコンのみ表示も Google のブランド規約が明示的に禁止しているので `blockButton` に固定。
