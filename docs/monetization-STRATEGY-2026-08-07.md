## 1. 発端と解いた対立

ユーザーの要望:
> 「APIを最大限に節約する方法と、マネタイズの導線・課金要素をしっかりして、ちゃんと黒字で回るようにしたい」
> 「使われれば使われるほど広告が出るとか、サブスクが増えるとか考えないと」

これは既存 SPEC と正面衝突していた。`cost-and-ads-ltv-SPEC.md` §2.4 は
「LTV = ARPU × 継続期間。ARPU 上限が低いため**継続期間を毀損する広告は数学的に必ず損**」として
新規7日間の広告ゼロ・1日3imp上限・D7継続率での撤退基準を定めている。

**結論: 対立は「見かけ」で、増やすべき変数の取り違えだった。**

増やすべきは「1人あたりの広告表示回数」ではない。それは上限が構造的に固定されており、
増やせば継続を毀損して数学的に損をする（既存 SPEC が正しい）。増やすべきは次の2つ。

1. **広告在庫は「人数」で増やす** — 1人3imp/日のキャップは不変のまま、
   総インプレッション = DAU × キャップ。**キャップは「1人を守る壁」であって「総収益の壁」ではない。**
2. **サブスク転換率は「蓄積データ」で増やす** — このアプリは正確な座標を永続保存する
   （CLAUDE.md 設計原則1）。使うほど「他では手に入らない自分の過去」が積み上がり、
   プレミアムの価値が単調増加する。**中核仕様がそのまま収益エンジンになる。**

## 2. 数字（LTV式）

### 1人あたり広告の上限は固定

前提: CTR 2% × CVR 2% × 報酬500円 → `EV/imp ≈ 0.2円`。
キャップ遵守で月24imp（月間アクティブ8日 × 3imp）。

```
広告ARPU上限 ≈ 24 × 0.2円 = 約5円/月/人
サブスク手取り = 400円 × 85%（Small Business Program）= 340円/月/人
```

> **有料会員1人 = 広告ユーザー約70人月分。**
> サブスク転換確率をわずかでも下げる施策は、広告収益で埋め合わせ不可能。

### 広告項は線形、サブスク項は凸

```
LTV = Σₘ R(m) · [ a + p(Nₘ) · s ]
  R(m): m ヶ月目の残存率   a: 広告ARPU（キャップで定数 ≈ 5円）
  p(N): 累計足あと N 件のユーザーが課金する確率（N について増加）
  s:    サブスク手取り 340円（課金後は残存期間ずっと発生）
```

広告項 `a·M` は生存月数に線形で天井が固定。サブスク項は二重に後乗せ
（p(N) はデータ蓄積で後の月ほど高く、課金後の売上も残り生存期間に比例）。
**継続悪化は「これから課金するはずだった月」を狙い撃ちで削る。**

### 3つの成長ループ（どれも継続を毀損しない）

| ループ | 何が増えると | 何が増えるか | 継続への影響 |
|---|---|---|---|
| **在庫** | DAU | 総インプレッション = DAU × 固定キャップ | ゼロ（1人あたり体験は不変） |
| **資産** | 累計チェックイン | 蓄積データの価値 → p(N) → 転換率 | **プラス**（記録が増えるほど辞めにくい） |
| **拡散** | Xシェア | 新規ユーザー。プレミアムがシェアページを飾れば拡散自体が広告になる | プラス |

**追うべき KPI は「累計足あと数 × プレミアム転換率」と「DAU」。**
広告収益は DAU 比例のボーナスとして扱い、**目標値を持たせない**
（目標化するとキャップを緩めたい誘惑が生まれる）。

## 4. プレミアム特典の再設計

### 既存設計への異議（§7 で覆す）

`monetization-DESIGN.md` E-1 は初回を **adFree + export の2機能**とした。
審査最安構成としては正しいが、**「毎月払い続ける理由」として構造的に弱い**。

- **adFree**: 広告在庫が自社カードのみの現在、「アプリ自身のお知らせを消すために400円」で価値ほぼゼロ。
  しかも審査員には保護期間で広告自体が見えない
- **export**: 一度書き出せば当面用が足りる**解約誘発型**。「1ヶ月だけ入って書き出して退会」が合理的行動になる

**「購入ボタンは押せるが、押す理由も押し続ける理由もない」状態で課金が始まる。**

### 新特典表（原則「あなたの過去は増え続ける」）

| 特典 | 価値の源泉 | 状態 | 優先 |
|---|---|---|---|
| **詳しい記録の眺め**（総移動距離・都道府県制覇率・月次推移） | 蓄積データ | 未実装 | **P0（購入開放と同時）** |
| 足あとの書き出し（GPX/GeoJSON） | 蓄積データ | 実装済 | P0（審査デモの主役として維持） |
| 広告非表示 | 在庫が育ってから効く | 実装済 | P0（コストゼロで同梱・訴求の主役にしない） |
| **旅の一年（年次リキャップ）** | 蓄積 + 拡散 | 未実装 | P1（年末なら最強の転換装置） |
| **シェアページの装い**（/u/{slug} テーマ） | X連携 → 拡散ループ | 未実装 | P1 |
| 足あとの印を選ぶ | 自己表現 | 未実装 | P2 |

**鉄則**: 記録と再訪（チェックイン・永続保存・地図・マッチ・図鑑・シェア）は**永久無料**
（ENTITLEMENTS.md 不変）。無料側を絞る課金は資産ループを自分で止める自殺行為。

### advancedStats 最小版（P0を軽くする）

購入開放と同時に出すのは統計3枚だけ: ①総移動距離 ②都道府県制覇マップ（既存の日本地図を流用）
③月別チェックイン推移。すべて `locations` の集計クエリ1本＋既存トークンで作れる（前提: 2〜3日）。

## 5. 導線設計

既存3導線（お知らせカード相乗り / マイページの静かな1行 / 機能ゲート接触時）は維持。
「押し売らず**本人のデータで語らせる**」2手を追加する。

1. **実データプレビュー**: 無料ユーザーにも統計1枚目（総移動距離）を**実データで**見せ、残りをロック。
   「あなたはもう 1,234km 歩いた。全部見るならプレミアム」——汎用の宣伝文ではなく本人の数字が売り文句になる
2. **節目の一言**: 10都道府県目・100チェックイン等の達成表示の下部に1行リンク。
   モーダル・プッシュ・カウントダウンは引き続き**全面禁止**

新規ユーザー保護期間（7日 or 10チェックイン）は**プレミアム訴求にも適用**。
p(N) は N が小さいうちほぼゼロで、見せるだけ損。

## 6. 黒字化の数値目標

### 固定費（前提。実請求は §8 で確認）

| 項目 | 月額換算 |
|---|---|
| Railway PostgreSQL | 約1,500円（前提: $10/月） |
| Apple Developer Program | 約1,082円（12,980円/年） |
| ドメイン | 約170円 |
| Vercel / GHA / Clerk / Groq / RevenueCat | 0円（無料枠） |
| **合計** | **約2,750円/月** |

### 損益分岐

```
必要有料会員数 = 2,750円 ÷ 340円 ≈ 8.1人 → 目標 10人
必要 MAU = 10人 ÷ 転換率 1〜2% = 500〜1,000人
```

- **有料10人（3,400円/月）**: 黒字化。広告はこの時点で誤差
- **有料50人（17,000円/月）**: Railway の成長と OGP 地図タイルの有料化を賄える
- **有料100人 + 直販2枠 = 44,000円/月**: 個人開発として十分。**ここまで広告キャップは緩めない**

**収益設計側で API を増やす要素はゼロ**（広告配信は既存 tRPC・統計は自DB集計・
RevenueCat は webhook 受動）。

## 7. 既存設計を覆す箇所

| 箇所 | 既存 | 本設計 | 理由 |
|---|---|---|---|
| monetization-DESIGN E-1 | 初回課金は adFree + export | **advancedStats 最小版を同梱して3機能** | E-1 は「審査に通る最安構成」の最適化で「売れる・解約されない構成」を見ていない。毎月価値が更新される特典ゼロで月額を開くのは転換率実測の機会を自ら潰す |
| cost-and-ads-ltv-SPEC §2.4 | 継続毀損広告は損 | **全面維持**。ユーザー要望と矛盾しないと再解釈 | キャップは1人あたりの制約で総在庫は DAU 線形（§2）。対立は変数の取り違え |
| monetization-DESIGN F | 買い切りは却下 | サブスク本体は維持。**年次リキャップ単品**は例外候補として v1.2 に付す | 却下理由（永続コストと不一致）は一回性成果物には適用されない |
| 広告3層の順序 | アフィリエイト → 直販 → プレミアム | **主軸をプレミアムに明示的に移す**。広告は DAU比例のボーナスに格下げ | §2 の 1:70 の比率。広告を主軸に置くとキャップ緩和圧力が生まれる |
