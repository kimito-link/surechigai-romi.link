## 4. このセッションで踏んだ地雷（同じ失敗を繰り返さないために）

すべて実測で確認し、修正済み。

### 4-1. Play / Android

**署名パッチの正規表現がブロックを飛び越えて誤検知**（`509162bc5`）
`/signingConfigs\s*\{[\s\S]*?\brelease\s*\{/` が signingConfigs を飛び越えて
buildTypes の `release {` にマッチし「もうある」と誤判定。
結果 `Could not get unknown property 'release'` でビルドが落ちるのに、
**スクリプトは「done」と出す**。波括弧を数える `findBlock()` に変更した。

**拡張子違いの同名画像で Duplicate resources**（`39c2e3c86`）
Android は assets を drawable にする際に拡張子を落とす。`logo.webp` と `logo.jpg` が衝突。
**8組あった**。Metro は参照の有無に関わらず assets/ を全部バンドルするので未使用画像も要因。
Web と iOS では起きず Play に出すまで気づけない。
`__tests__/asset-name-collision.test.ts` で固定済み。

**versionCode が 1 固定**（`e9c462220`）
prebuild が毎回書くので手修正は無意味。初回は通るが2回目で必ず衝突。
`GITHUB_RUN_NUMBER` で採番し、**書き込み後に読み返して検証**する
（iOS で「注入したはずの値が入らず5連続失敗」した前例があるため）。

**プラグイン登録を外すだけでは権限が消えない**（`82b90af66`）
`expo-audio` を plugins から外していても、依存にある限りマニフェストマージで
`FOREGROUND_SERVICE_MEDIA_PLAYBACK` が入る。Play の申告画面で「その他」を選ぶと
**用途を示す動画の提出**まで求められた。依存ごと削除して申告項目自体を消した。

**公開ステップだけ TWA のパスが残っていた**（`e9c462220`）
ビルドは通るのに最後の1歩で `AAB not found`。移行時の直し漏れ。

### 4-2. Play Console の UI 側

**ストア言語が en-US で作られる**
アプリ作成時のデフォルトが en-US のまま。スクリプトの既定は `ja-JP` なので投入先が食い違う。
ja-JP を作成し、空だった en-US は削除した（削除しないと「一部の言語にエラー」で送信できない）。

**カテゴリを「ソーシャル」にすると「子どもの安全基準」が必須になる**（`d976917dd`）
CSAE に対する方針を**外部に公開したページ**として示す必要がある。
`/terms` を登録したが、実際には「13歳未満は利用できません」の1行しかなく実態が伴っていなかった。
利用規約に第5章「子どもの安全（児童の性的虐待・搾取の禁止）」を新設して解消。
**この章を消すと申告と食い違う**ので、コード側にもコメントで警告を残してある。

**製品版トラックにリリースを作らないと送信できない**
CI は internal に上げる設定。製品版は別途「新しいリリースを作成」→ライブラリから vc を選ぶ。
配信国（日本）の選択も製品版だけの必須項目で、内部テストには無いので見落としやすい。

### 4-4. iOS build 495 の起動クラッシュ却下（2026-08-13・修正済）

**却下内容**: Guideline 2.1(a)。iPad Air 11-inch (M3) / iPadOS 26.6 で起動即クラッシュ。
`.ips` 2本が添付された。

**真因**: `expo-dev-client` が `package.json` の **`dependencies`** に入っていた。
リリース IPA に `EXDevMenu` / `DevMenuManager` が焼き込まれ、起動直後の
TurboModule 初期化で uncaught な ObjC 例外 → `abort()`。

> ⚠️ **ソースからの import が 0 件でも安全ではない。**
> expo の autolinking は `dependencies` にあるだけでネイティブモジュールを取り込む。
> これは 08-12 の expo-audio 権限混入（プラグイン登録を外すだけでは足りず依存ごと
> 削除が必要だった）と**まったく同じ型**。「使っていないから安全」は成立しない。

**決定打になった手順**（推測を重ねるより速い）:
```bash
gh run download <run-id> -n ios-ipa-appstore   # 提出物そのものを取得
# バイナリを取り出して文字列 grep → EXDevMenu が 7 箇所ヒットで確定
```
`.ips` のシンボル化は**無意味だった**。ストリップ済みで symtab が519件しかなく、
`+0x141e0` のような遠い前方シンボルしか出ない。文字列 grep に切り替えるのが正解。

**`.ips` の読み方**: 1行目がJSONヘッダ + 2行目以降がJSON本体の2部構成。
`json.loads(raw[raw.index('\n')+1:])` で本体が読める。
2本は別症状で、片方だけ見ると誤診する（`EXC_CRASH`/SIGABRT の TurboModule 例外と、
`EXC_BAD_ACCESS`/SIGSEGV の `setNativeState` は同じ初期化の別の死に方）。

**この調査で否定した仮説2つ**（もっともらしいが誤り。同じ道を辿らないこと）:
1. 「iPad で審査されたのは `supportsTablet: false` が効いていないから」→ **誤り**。
   IPA の `UIDeviceFamily` は `[1]` で iPhone 専用は正しく効いていた。
   iPhone 専用アプリを iPad の**互換モード**で起動するのは Apple の正常な審査手順。
2. 「JS バンドルが HBC 化されていない」→ **誤り**。`main.jsbundle` の先頭8バイトは
   `c61fbc03c103191f` で正常な Hermes バイトコード。

**再発防止**: `scripts/lint-pre-submission.mjs` に **CHECK 9**（`dev-only-deps`）を追加。
`expo-dev-client` / `expo-dev-menu` / `expo-dev-launcher` / `react-native-flipper` が
`dependencies` にあれば fail。**バグを再導入して実際に落ちることを確認済み**
（grep ベースのテストが緑のまま素通りした過去の反省を適用）。

**検証**: build 499 の IPA を再取得し、dev-menu シンボルが **0件**になったことを実測。
ただしこれは静的検証であり、実機起動そのものは試していない。
