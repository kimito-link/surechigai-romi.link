## 1. UI/UX: レスポンシブ監査の警告を正しく仕分ける（最優先）

`node scripts/qa/responsive-audit.mjs` が大量の WARN を出すが、
**実測したところ大半が誤検知**だった。このままだと警告が狼少年になり、
本物の不具合が埋もれる。**仕分けてノイズを消すのが仕事**。

### 1-A. タップ標的の警告は「全て Clerk 内部要素」＝除外する

`/sign-in` の全7ビューポートで `smallTargets` が出るが、実体は次の3つだけ：

| 高さ | href | class |
|---|---|---|
| 36px | `https://kimito.link/` | `cl-internal-13qvwbc` |
| 18px | `.../sign-in`（サインアップ） | `cl-footerActionLink cl-internal-ngux` |
| 14px | `https://go.clerk.com/components` | `cl-internal-1scxde7` |

**3件とも Clerk が描画する要素**（`cl-` プレフィックス）。
CLAUDE.md の鉄則により**書き換え禁止**なので、直してはいけない。

→ `scripts/qa/responsive-audit.mjs` の `smallTargets` 判定で、
**`cl-` で始まる class を持つ要素を除外**する。
除外したことがレポートで分かるよう、除外件数をカウントして出力に含める
（黙って消すと「検査していない」のか「問題が無い」のか区別できなくなる）。

### 1-B. 小さすぎる文字（tinyText）も大半が意図的

出現回数の実測（上位）:

```
42回  v1.0.0                       [11px]
36回  君斗りんくのすれ違ひ通信        [11px]
30回  キミトリンク · Kimito-Link…    [10px]
18回  チェックイン                   [11px]  ← タブラベル
18回  マイページ                     [11px]  ← タブラベル
 7回  SURECHIGAI TSUSHIN            [11px]
 6回  1 人が記録中                   [10px]
```

- **バージョン表記・フッターのブランド表記・タブラベル**は意図的に小さい。除外してよい
- ただし **`1 人が記録中`（10px）は本文情報**。これは読ませたい情報なので
  **12px 以上へ引き上げる**（該当箇所を grep で特定すること）

→ 判定に「除外セレクタ（フッター・タブバー・バージョン表記）」を導入し、
残ったものだけを WARN にする。**閾値を緩めて黙らせるのは禁止**（それでは検査にならない）。

### 1-C. 認証済み画面が監査対象外になっている

`ROUTES` に `/mypage` 等はあるが、**ゲストで開くとログイン画面にリダイレクトされる**ため
実質「認証後のUI」は一度も検査されていない。
`scripts/save-auth-state.mjs` で保存した auth-state を使う監査モードを足す
（`e2e:audit` に `audit-auth-*` プロジェクトが既にあるので、そちらとの重複に注意。
既存で足りるなら**新規に作らず既存を使う**）。

> ⚠️ auth-state の取得は X OAuth ログインが要り、人手が必要。
> 取得できない場合はここはスキップして、その旨を報告すること。**偽の緑を作らない。**
