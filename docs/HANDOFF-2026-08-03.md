## 1. このセッションでやったこと

### レスポンシブ最適化（ユーザー報告の不具合対応）

**真因は入力欄の fontSize が 16px 未満だったこと**だった。
iOS Safari は 16px 未満の input にフォーカスすると**ページを自動拡大し、戻さない**。

修正した7ファイル（すべて 16px へ）:
`ui/input.tsx(sm)` / `map/place-note-modal` / `events`×4 / `mypage/delete-account-control`

### 監査ツールをログイン後画面に対応（最重要の改善）

`scripts/qa/responsive-audit.mjs` に `--auth` を追加した。

```bash
node scripts/qa/responsive-audit.mjs --base https://surechigai.kimito.link \
  --auth .auth/auth-state.json --routes /,/checkin,/map,/zukan,/events,/mypage
```

**これが無いとゲスト画面しか測れず、実際に不具合が出ている認証後画面を見逃す。**
実際、ゲストでは0件だったのにログイン後を測って初めて検証できた。

### 実測結果（ログイン済み `@idolfunch`・42通り）

### 罠B: auth-state の取得（3つ踏んだ）

1. **`pnpm e2e:auth-save` は使えない** — Google/X が自動化を検知して弾く
   （「このブラウザまたはアプリは安全でない可能性があります」）。
   → `node .tmp-auth-save-patchright.mjs`（Patchright + 実Chrome）を使う
2. **保存が早すぎると `__client_uat=0`（未ログイン）で保存される** —
   X の認可完了後も Clerk のセッション確立は非同期。
   `window.Clerk.user` が入るまで待つよう修正済み
3. **`ROOT` が `".."` だと親ディレクトリに保存される** — 修正済み

`.auth/auth-state.json` は**有効な状態で保存済み**（`@idolfunch`）。
期限切れになったら上記スクリプトで取り直す（ユーザーの手動Xログインが要る）。

## 3. 次にやること（推奨順）

### 3-1. 審査結果を待つ → 却下されたら store-guard

`WAITING_FOR_REVIEW` のまま。通常24〜48時間。結果は登録メールに届く。
却下されたら `store-guard` エージェントに却下理由を渡す
（`_docs/apple-reject-knowledge-base.md` と照合して返信案を作る）。

**再提出は `gh workflow run ios-appstore-release.yml` 一発**で通る。
初回に必要だった手作業（App Privacy 公開・配信国設定）は済んでいる。

### 3-2. 未検証の領域（ユーザーが気にしている）

ユーザーは「まだ不具合がたくさんあると思う」と言っている。実際、
**監査が見るのはレイアウトと表示だけ**で、以下は未検証:

- **Xアカウントを切り替えたときの挙動** ← ユーザーが明示的に挙げた
- 複数アカウント間の状態遷移
- ネイティブ実機での Apple ログイン（EAS ビルド後の実機確認）

`forceSwitch`（先に signOut してから認可し直す）は
`components/providers/clerk-auth-bridge.tsx:190` に実装済みだが、
**ログイン画面から呼ばれていない**。「別のアカウントでログイン」導線を
足すかはユーザー判断待ち。

### 3-3. Android 提出

`app.config.json` の `stores` で `playAppId` / `playDeveloperId` が空欄。
`bootstrap-secrets.mjs` で登録できるが、鍵が3つ足りない:
`GOOGLE_PLAY_SA_JSON_BASE64` / `ANDROID_KEYSTORE_BASE64` / `ANDROID_KEYSTORE_PROPERTIES`

### 3-4. 課金の有効化

`PURCHASE_AVAILABLE = false`（`app/premium.tsx`）を true にするには
RevenueCat の SDK 導入とストア商品登録が要る。設計は
`docs/monetization-DESIGN.md` にあり、**初回提出に入れない方針は意図的**。

## 4. 触ってはいけないもの・方針

- **`CDN_CACHE_EPOCH`（現在29）**: デプロイが反映されないときに +1 する。
  Metro の同名別内容チャンク対策。`version.json` 一致はデプロイ証明にならない
- **入力欄は必ず 16px 以上**。下回ると iOS が自動ズームして画面が壊れる
- **`clerk-root-provider.tsx` / `clerk-auth-bridge.tsx` 以外で
  Clerk の React フックを呼ばない**。Provider の外で走ると全画面が落ちる
  （2026-07-31 と 08-01 に2度発生）
- **ローカルの green を根拠にしない**。本番ビルドの実チャンクを grep して確かめる
