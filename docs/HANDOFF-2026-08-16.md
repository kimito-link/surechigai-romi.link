## 4. 踏むと分かりにくい形で壊れる地雷

### 4-1. ストア申請まわり（今回3回踏んだ）

**push 起動の iOS リリースは提出しない。**
`force_resubmit` は `workflow_dispatch` の入力なので、push だと空になる。
審査待ちのバージョンがあると `Nothing to do.` と出して**緑のまま未提出**で終わる。
build 506 がこれで無駄になった。

```bash
gh workflow run ios-appstore-release.yml -f force_resubmit=true
```

**その手動実行が直後の push に潰される。** 後発が先発をキャンセルする設定のため、
2回連続で `cancelled` になった。**push を先に完走させてから** dispatch すること。

**Play のリリースノートは500文字上限。** `PLAY_KEEP_RELEASE_NOTES=1` が設定済みで
手書きが保持されるため、長さがそのまま効く。書いたら測る:

```bash
node -e "console.log(require('fs').readFileSync('release-notes/CURRENT-ja.txt','utf8').length)"
```

**`No rejected versions found.` は「通った」ではない。** 却下が無いだけ。
提出の有無はリリース実行のログで `PATCH submitted=true` と `final state` を見る。

### 4-2. コード側

| 地雷 | 内容 |
|---|---|
| `git add -A` 禁止 | `.npm-cache/` を巻き込み commit が3分でタイムアウトし、作業ツリーが巻き戻った。`.gitignore` に追加済みだが**ファイル明示指定**を習慣に |
| `useToast` の位置 | `ClerkRootProvider` の内側でしか呼べない。外だと画面全体が落ちるが**tsc は通る** |
| `use-live-presence.ts` | 依存配列に mutation を入れると429の嵐（実績あり）。戻り値の後処理だけに留める |
| 動的 import | Hermes の Release ビルドだけで落ちる（exifr の前科）。アプリ本体では静的 import を使う |
| CDN_CACHE_EPOCH | デプロイしても反映されない時は `theme/tokens/index.ts` を +1。今回 32→33 にした |
| CSP | 外部APIをブラウザから直接叩けない（`vercel.json`）。`/api/` で中継する |
| `pnpm db:push` | 使えない。マイグレーションに4つの罠がある |
