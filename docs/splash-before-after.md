# 起動画面 — 変更前と変更後

2026-10-26。ストア提出も本番デプロイもしていない。

## 変更前（実機で見えていたもの）

1. iOS でアイコンをタップすると、約1秒の黒い画面のあと本編が急に出る。ロゴは見えないことがある。別のときだけ、ロゴのあと別の読み込み画面が出る。
2. Web とアプリ内で「すれ違ひ通信」に入るとき、起動画面がチカチカする。ロゴ、スピナー、別レイアウトの待ちが短い間に続く。

## 原因

- `userInterfaceStyle: "dark"` のまま、起動画面の地色に暗色バリエーションが無かった。iOS はその名前付き色を黒で塗る。
- `preventAutoHideAsync` が無く、ルートビューが付いた瞬間に起動画面が消える。その下はまだ黒。
- 消えたあとに、別の絵の待ち（ロゴ＋ゆっくり＋スピナー、またはマーク＋タイトル＋スピナー）が出る。Web のベールはログイン中ヒントか PWA のときだけ後から付き、地色も本体（`#F0F4F8`）と起動画面（`#E2EDF7`）で違った。
- Android 12+ は起動アイコンを円で切る。全面の構図をそのまま渡すと円の中で切れる。

## 変更後

- 起動中は1枚。ワードマーク、地図ピン、ゆっくり（きつね・りんく・たぬき）、タグライン「キミの現在地を、刻む。」。地色は `#E2EDF7`。
- iOS のネイティブ起動画面と、最初の JS フレームと、Web の HTML ベールが同じ地色・同じ構図。本編の準備ができてから 280ms のフェードが1回。`prefers-reduced-motion` では待たずに外す。
- Web の絵は `app/+html.tsx` の data URI。外部 CDN も画像の取得も待たない。ロックダウンモード（JIT 無し・外部フォント無し）でもシステムフォントとこの HTML/CSS で出る。
- Android の OS 起動アイコンは円に収まる透過のゆっくり＋ピン。地色は同じ。全面の構図は円で切れるため、OS アイコンには使わない。
- 起動後のタブ待ちは、同じ絵をもう一度出さない。文言つきの途中読み込み（軌跡など）はスピナー付きの全面画面にしない。

## 確認のしかた

- ネイティブのコールドスタート: 新しいバイナリで、アイコンをタップした直後から地色と絵が出て、黒が挟まらず、本編へ1回フェードする。暗い外観の端末でも同じ。
- Web: 本番またはプレビューを再読み込みし、最初の塗りが `#E2EDF7` の起動画面であること。白や黒が先に出ないこと。本編へ1回だけフェードすること。開発者ツールで `prefers-reduced-motion: reduce` にするとフェードが無いこと。
- アプリ内: ホーム、軌跡、図鑑、現在地、マイページ、`/u/<slug>` へ入ったとき、別のロゴやスピナーが連続しないこと。

## ストアのバイナリは必要か

必要。ネイティブの起動画像、`userInterfaceStyle`、スプラッシュの `backgroundColor`、`expo-system-ui` はアプリのバイナリに入る。既存のインストールには OTA だけでは届かない。

Web の HTML・CSS・`public/boot-splash.png`・PWA 用の起動画像は、Web のデプロイだけで届く。ストア提出は要らない。

この変更ではバージョン番号を上げていない。ワークフロー、fastlane、eas の submit、twa-manifest、ストア用メタデータは触っていない。提出は別作業。
