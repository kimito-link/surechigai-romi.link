# 調査＋会議の結果: 「ジモティのようにみんなが使うもの」にするには

> 実施: 2026-09-08 / 司令塔(Claude Opus 5) が統合・裏取り
> 材料: ①本番DBの実測 ②公開情報調査（ジモティ利用者の困りごと） ③マルチLLM会議（6体・201秒）
> ★正本 `../../web-ios-android/docs/ai-workflows/COUNCIL-HOWTO.md` の手順に従う。
> 会議の主張はすべて実コード・実DB・出典で裏取りしてから採用した。

---

## 0. 結論（先に書く）

**「ジモティのようにみんなが使うもの」を正面から目指すのは非現実的。**
根拠は規模差（ジモティ MAU 約1,000万・東証グロース上場 vs このアプリ実ユーザー0）ではなく、
**中核機能「すれ違い」が人口密度を必要とし、鶏卵問題を自力で破れない**こと。

★ただし調査は**別の道**を示した。オーナーの仮説の「課題側」は強く裏付けられ、
「解決手段側」には明確な逆風がある。**課題は正しく、手段を選び直すべき**というのが統合結論。

## 1. 実測（本番DBを直接集計・2026-09-07）

```
総ユーザー 8人（★全員オーナーの知り合い＝実ユーザー0）
30日以内ログイン 1人（オーナーのみ）／7人全員が登録日＝最終ログイン日
足あと 206件（オーナー175件＝85%）
場所メモ 0件／リアクション 0件
集まり 10件（開催 6/16〜7/17。以降2ヶ月ゼロ）
すれ違い成立 5件（8/02〜8/11のみ）
地理分布: 長野県4人・東京都2人
アクセス解析 ★未導入（訪問者数を測る手段が無い）
```

**★オーナー自身の利用は本物**（会議で争点になったので精査した）:
```
実際に使った日数 45日／直近30日で15日／月別 6月31件→7月86件→8月53件→9月5件
```
＝ **2日に1回使っている**。「作った人が惰性で触っている」水準ではない。

## 2. 公開情報調査: オーナーの仮説はどこまで正しいか

### ★仮説の「課題側」は強く裏付けられた

1. **ドタキャンは運営公認の定型トラブル**。ジモティ公式のトラブル5類型のうち**2つ**が
   ドタキャン系（「待ち合わせ当日の連絡不通」「ドタキャン」）で、**専用の対策ページまである**。
   ⟹ オーナーの体験は n=1 の不運ではなく、**運営が想定している構造的問題**。
2. **★既存の信頼シグナル（評価）が構造的に効いていない**（これが最大の発見）。
   - 報復評価を恐れて低評価が抑制される（解決広場に複数の訴え）
   - **ドタキャンした側は「取引完了」しないので、そもそも低評価を付けられない可能性**
   - 運営は**通報の処分結果を開示しない**（公式FAQに明記）→ 抑止力が実感されない
   ⟹ **「悪い人が悪い評価を持たない」状態が生まれうる**。別の信頼シグナルへの需要は理論上ある。
3. **ユーザーは既に「人となり」で判断しようとしている**（「評価ゼロの人は避けるべきか」
   「文体を確認する」といった投稿が多数）。判断材料への渇望は実在する。
4. **同じ発想が Facebook Marketplace で実装済み**（相手のプロフィール・投稿履歴・
   アカウント作成時期を見て判断せよ、が標準ガイダンス）。

### ★仮説の「解決手段側」には明確な逆風がある（正直に書く）

1. **業界の信頼標準は「SNS」ではなく「政府発行ID検証＋レビュー」に収束**。
   Airbnb は 2013年の Verified ID から liveness・顔照合まで進化し、SNS連携には行っていない。
2. **国内最大手はSNS連携を明確に禁止**。メルカリはプロフィール・メッセージへの
   SNS ID記載を禁止行為に指定している。
3. ★**SNSプロフィールが見えても詐欺は防げていない**。Facebook Marketplace は実名・
   プロフィール可視なのに詐欺記事が大量にある。＝「見える＝安心」の**反証**。
4. **日本は実名開示への抵抗が国際的に突出**（実名開示抵抗 日本60%超 vs 他国30-40%／
   Facebook日本利用率25%未満。★数値は一次確認未達）。SNS必須にすると母数が激減しうる。
5. ★**既に「別解」が実装・運用されている**。Yahoo!フリマの「安心取引出品者バッジ」は
   **キャンセル率**を直接シグナル化。SNSを介さず同じ課題を解いている。
6. **ドタキャン頻度の体感が極端にばらつく**（「ゴロゴロいる」の一方、2700回取引で
   「一度もない」という回答も）。全員が困っているわけではない。

## 3. 会議の結論（6体・201秒。★裏取り済みのものだけ載せる）

### 争点1: 「価値が存在しない」のか「価値が伝わっていない」のか

- **批判役（groq/gpt-oss-120b）**: 「8人全員が1日で離脱＝価値が存在しないことを示す。
  即座に全機能を凍結し、取引支援だけに絞れ」
- **発散役（groq/qwen3.8-27b）が反論**: 「開発者本人が3ヶ月・月50〜80件残し続けている事実は、
  価値が**存在する**ことを示す。これは『認知不足』ではなく**共感できる層が極めて狭い**問題」

★**司令塔の裁定: 発散役を採る。** 実測（45日利用・直近30日で15日）が反論を支持する。
ただし「層が狭い」は事実として受け入れる。

### 争点2: すれ違いの鶏卵問題

会議は**全員一致で「全国規模のすれ違いは物理的に不可能」**と判定。
長野県4人・東京都2人という実測がそれを裏付ける（すれ違い成立は8/2〜8/11の5件で止まっている）。

- 発散役の案: **長野市駅周辺など特定の高密度エリアに限定**し、オフラインイベントで種火を作る
- ★リスクとして本人が挙げた失敗シナリオ: 「来場者が集まらず開発者1人の自己満足イベントに終わる」

### 争点3: 次の一手

会議の多数意見は「**機能追加でも集客でもなく、まず価値検証**」。
ただし提案された手段（X上でアンケート・デモ動画）は、
★**オーナーの制約「アンケートは使えない」と衝突**しており、そのままは採れない。

## 4. ★司令塔の統合結論（会議＋調査＋実測を突き合わせた）

### 4-1. 「みんなが使うもの」は目標として設定し直す

ジモティ MAU 1,000万に正面から挑むのではなく、
**「ジモティの弱点を、ジモティの外から補う」**位置に立つ。

★根拠: 調査で判明した「評価制度の構造的欠陥」は、**ジモティ自身が直せない**
（報復評価も、取引完了しないと評価できない仕様も、処分非開示も、
プラットフォーム内で完結させようとする限り解けない）。
外部から補うプレイヤーには余地がある。

### 4-2. ★ただし「Xを見せる」だけでは弱い。実測で確認した「別解」を併せ持つ

調査で見つかった Yahoo!フリマの**キャンセル率バッジ**方式は、このアプリで**作れる**（実コードで確認）:

| 必要なもの | 実測結果 |
|---|---|
| 参加表明の記録 | `eventParticipations` に実在。★`deletedAt` があるので**取り消しも記録される** |
| 約束の記録 | 同上（`eventId` + `userId` + `createdAt`） |
| Xの信用情報 | ★`twitterUserCache` に `followersCount`・`description` が**既にキャッシュ済み**（7件） |
| 実際に行った証跡 | `locations`（正確座標・永続保存） |
| ★会場の座標 | **無い**（`venueName` の文字列のみ）＝ 自動照合には追加が必要 |

⟹ **「Xの人となり」＋「約束を守った記録」の二本立て**にできる。
★片方（SNS）だけでは Facebook Marketplace の反証に当たるが、
**行動の記録と組み合わせれば別物**になる。

### 4-3. 順番

1. ★**計測を入れる**（訪問→登録→2日目。現状測る手段が無く、他の判断が全部盲目）
2. **エリアを絞る**（長野市など、オーナーが実際に動ける範囲）。全国は捨てる
3. **既存機能が使われない理由を1つ潰す**（場所メモ0件・リアクション0件は
   「作ったが使われない」の実例。新機能を足す前にここを理解する）
4. 上記が済んでから、`docs/category-meetup-navi-*` の設計（カテゴリ／会いに行く／自宅に帰る）
   に着手するか判断し直す

## 5. ★この調査で「測れなかった」こと（憶測で埋めない）

- ドタキャンの**定量的な発生率**（運営・第三者いずれの統計も公開されていない）
- 「無断キャンセルで利用停止」の**実際の執行状況**（運営が結果非開示のため原理的に検証不能）
- このアプリの**訪問者数**（アクセス解析が未導入）
- 実名/SNS連携必須にして**失敗した具体的サービス名**
- 日本の実名開示抵抗の数値（複数記事が同方向を示すが**一次資料に未到達**）

## 6. ★会議の提案のうち、採らなかったもの（理由付き）

| 提案 | 却下理由 |
|---|---|
| X上でアンケートを取る | ★オーナーの制約「アンケートは使えない」と衝突 |
| 「信用スコア」を算出して色分け表示 | ★根拠を説明できない数字は信用を損なう。フォロワー数が多い＝約束を守る、ではない |
| 全機能を即凍結して取引支援だけに絞る | ★オーナー自身が45日使っている足あと機能を消すのは、唯一の実利用を捨てること |
| 「人通りの多いルートを提案する安全ナビ」 | ★人通りのデータを持っておらず、実装不能（会議の幻覚） |
