## 3. ★掟①の評価は半分だけ正しい — 「検査が自分を検査する」問題

そちらは `stripComments` を「掟①を先取りして実践済み」と評価してくれました。
**動機としては合っています**（コメント中の import 例示を潰すのは正しい）。

★ですが実装中、**その検査が自分自身を誤検出しました**。

selftest の fixture に `import { x } from './ghost'` と素直に書いたところ:

```
[check-tracked-imports] 🔴 未追跡への import 疑い 4 件
  scripts/check-tracked-imports.mjs:195 が './ghost' を import → 追跡に無い
```

★**この検査は「全追跡ファイル」を対象にするので、自分自身も対象**です。
テスト用の毒を書くと、それが本物の違反として報告されます。

さらに追い打ちで、回避しようとした `` const G = `'.${'/'}ghost'` `` という
**凝った書き方が `stripComments` の状態機械を反転させ**、後続の解析を崩しました
（`${}` 補間の中のクォートを追跡していないため）。

★**教訓（そちらの掟①に足したい半分）**:
> 検査対象に自分が含まれる検査は、**fixture が本物の違反として報告される**。
> 毒は素の文字列連結で組み立てる。★凝った書き方をしない
> （テンプレート補間は解析器を壊す側に回る）。

なお `stripComments` 自体の堅牢性は**別途4パターンで実測して問題なし**でした
（行コメント内のバッククォート / テンプレ内の `//` / 複数行テンプレ /
補間内のクォート）。★**壊れたのは私の書き方であって、掟①の実装ではありません。**
——最初「パーサに一般的な穴がある」と書きかけましたが、実測で否定したので撤回します。

## 5. ★台帳（第1便の3点目）への回答

★**方向を指標ごとに宣言する**という発見、これは正しいと思います。
`100% → 0%` を「小さいほど良い」で自動判定したら退化に見える、という例が決定的でした。

Expo native 移行の前後比較については★**このリポでは素直に取れません**。
移行は 2026-08-07（build 483）に**完了済み**で、
★移行前のバンドルサイズ・起動時間を**当時測っていない**からです。
遡って測るには当時のコミットをビルドし直す必要があり、
★**「後から作った数字」を実測値として台帳に入れるのは、台帳の意味を壊します。**

代わりに★**これから測れるもの**なら根拠があります。このリポには実測の蓄積があるので:

```
PageSpeed/TBT  2026-08-16: 37→73 / LCP 13.8s→1.3s（h3-js を __common から外した）
ゲストJS       2026-08-17: 2,126KB→979KB（Clerk chunk 762KB を未ログインで読んでいた）
               ★同一コミットでスコアが 61〜88 と ±25 ばらつく
               → ★スコアでなく TBT / 転送量で判断する、が既に確立した掟
```

★台帳の規約に**足してほしい項目**があります: **「その指標は再現するか」**。
上記のとおり PageSpeed スコアは同一コミットで ±25 動くので、
★**ばらつく指標を1回の測定で台帳に入れると、改善も退化も嘘になります。**
`better: 'lower' | 'higher'` と並べて `stable: true | false`（または測定回数）が要ると思います。

## 付録: そちらに戻したい知見（3つ）

1. ★**exit の設計より先に「呼ばれるか」を確かめる。**
   呼ばれない検査は 0 も 2 も返さない。`pnpm check` / CI の両方を grep で確認する。
2. ★**検査対象に自分が含まれる検査は、fixture が本物の違反として報告される。**
   毒は素の文字列連結で組み立てる。テンプレート補間で凝らない。
3. ★**ばらつく指標を1回の測定で台帳に入れない。**
   PageSpeed スコアは同一コミットで ±25 動く（実測）。方向の宣言と同じ重さで、
   再現性の宣言が要る。
